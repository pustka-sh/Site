# Published documentation discovery

Published version routes return the actual guide or API content in their initial HTML. Readers and search crawlers can follow versioned overview, guide, API index, symbol, adjacent guide and exact-commit source links without JavaScript. API signatures, descriptions, parameters, returns, exceptions, deprecation and stability policy appear in semantic headings and tables. The service's sanitized Markdown and math output is reused; uploaded raw HTML never becomes trusted markup.

`renderPublishedDocumentation(template, {manifest, page, symbol, origin, pathname, symbolId})` returns an HTML string. `manifest` is the published service manifest. `page` and `symbol` are the inner objects returned by the service's page/symbol methods, or `null`. `symbolId` is the exact decoded symbol query parameter. `origin` must be the configured site origin, never the request Host header. `pathname` is the selected documentation route. The existing `documentationHtml(template, {title, description, url})` export is retained; optional `body` and `extraHead` accept trusted, already-rendered markup for other generated pages.

The initial response includes a nonexecuting `<template id="pustka-doc-bootstrap">` outside the React root. JSON is HTML-escaped, protecting closing-template strings and authored markup. The reader parses the template's decoded `textContent` as data and uses exact existing API paths for the manifest and selected page/symbol response. React starts with those resources instead of replacing useful content with a loading state or refetching the same snapshot. The initial effect remains safe when React StrictMode replays it. Navigation to other resources and older static shells without a template retain the same-origin API fetch path. No additional executable inline script or relaxed content-security policy is needed.

The top-level `/sitemap.xml` is a sitemap index. Mount it before static middleware. It includes `/sitemaps/site.xml` (the existing generated static sitemap) and `/sitemaps/docs/:project/:version.xml` for registry-backed published snapshots. `documentationSitemapIndex({documentation, origin, staticPages})` and `documentationVersionSitemap({documentation, origin, project, version})` return XML strings. `staticPages` is optional; objects with a `lastmod` publication timestamp can supply the static map's last modification date. Serve `dist/sitemap.xml` at `/sitemaps/site.xml` without redirecting it back to the index.

Version maps include the version overview, every guide, the API index and individual symbols. Their `lastmod` uses the snapshot's exact publication timestamp, rather than package generation time or current request time. Drafts, preview artifacts and unpublished versions are excluded. Both URL and XML escaping are applied. Maps are bounded to 50,000 entries and 50 MiB. Symbol URLs beyond the sitemap protocol's 2,048-character limit are omitted from XML while staying linked in the full API index. No visitor-controlled external URL enters a sitemap.

Focused checks: `node --test test/documentation-html.test.mjs test/documentation-sitemap.test.mjs`. These cover initial no-JavaScript content, source/version links, metadata escaping, malicious closing-template data, old-client fallback, draft exclusion, publication dates and sitemap bounds.
